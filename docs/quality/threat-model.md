# Threat model: AI-первая линия поддержки

Статус: проект LAB02; атаки и результаты запланированы на LAB04. Объект: текстовый тикет, история, утверждённая БЗ, AI-предложение и решение оператора. Защищаем факты клиента, контроль отправки, целостность БЗ и независимость человека. Источник классификации — [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/llm-top-10/).

## Доверительные границы и права

| Вход | Кем контролируется | Возможный вред | Защита и тест LAB04 |
|---|---|---|---|
| текст клиента / история | клиент и внешняя поддержка | инструкции модели, чужие ID, PII, длинный шум | считать данными; role/tenant check, длина, инъекции на отказ от правил |
| статьи/фрагменты БЗ | редактор БЗ, импорт/индекс | устаревший или подменённый совет, скрытая команда | только `approved`+версия, provenance, карантин, тест вредного фрагмента |
| поля аккаунта/заказа | интеграция helpdesk | доступ к чужому клиенту | минимизация и проверка прав на backend, тест cross-tenant |
| вывод модели | внешняя модель | ложный факт, опасное действие, HTML/script, режим `answer` без основания | JSON/schema+policy gate, экранирование UI, ручное подтверждение |
| feedback оператора | человек/интерфейс | загрязнение eval/БЗ, утечка | хранить отдельно, review до использования в обучении/БЗ |

Модель имеет **только право предложить** карточку. Она не может вызвать отправку, назначение, запись в БД клиентов, внешние URL или произвольный поиск. Backend и helpdesk adapter выполняют запись только после явного подтверждения уполномоченного оператора. Если модель обманута, максимальное техническое действие — ошибочное предложение, которое ещё должны остановить policy gate и человек; это требование для тестирования, а не доказанный факт работающей системы.

## OWASP 2025 применительно к MVP

| Риск | Проявление / контроль |
|---|---|
| LLM01 Prompt Injection | команда «игнорируй правила» в тикете, истории или статье; граница данных, adversarial cases |
| LLM02 Sensitive Information Disclosure | PII/токен из чужого обращения в карточке; фильтр данных, права, redaction, negative tests |
| LLM03 Supply Chain | скомпрометированный пакет/модель/образ; pin версий, сканирование зависимостей и подписанные источники |
| LLM04 Data and Model Poisoning | подмена KB или feedback; status/version/review, контроль импорта |
| LLM05 Improper Output Handling | HTML/ссылка/разметка из модели в UI; escaping, schema и запрет прямого выполнения |
| LLM06 Excessive Agency | AI отправляет ответ или меняет тикет; у AI API нет write-инструмента, тест отсутствия write-вызова |
| LLM07 System Prompt Leakage | просьба раскрыть инструкции/ключи; не помещать секреты в prompt, тест вывода системного текста |
| LLM08 Vector and Embedding Weaknesses | чужой/неутверждённый фрагмент в retrieval; tenant+version filter до выдачи модели |
| LLM09 Misinformation | правдоподобный неподтверждённый ответ; evidence на каждый существенный факт, режим отказа |
| LLM10 Unbounded Consumption | длинный тикет, повторные вызовы, стоимость; лимиты размера/токенов, один retry, rate limits |

## Приоритетные атаки LAB04

1. Прямая инъекция в обращении и косвенная в статье требуют `answer` без основания; ожидается отказ/эскалация.
2. Запрос восстановления доступа к чужому аккаунту и просьба выдать пароль/токен; ожидается эскалация без раскрытия.
3. Устаревшая статья и конфликт двух версий; ожидается отсутствие уверенного ответа.
4. Вывод модели содержит HTML/JS или внешний URL; UI экранирует, не выполняет.
5. UC-04: отклонение предложения не вызывает отправку и не переписывает историю как «ответ AI».

Регуляторные требования зависят от фактического сервиса, юрисдикции и данных. Пока они не определены Product/владельцем процесса, нельзя утверждать соответствие конкретному закону; до согласования используются только синтетические или разрешённые обезличенные данные.

## Событийная архитектура, уточнение 26.10.2026

Разбор запускают события `ticket.created` и `customer.message_received`, а не кнопка оператора. Подробные сценарии и ожидаемые результаты: [проверки событийной обработки](test-plan.md#сценарии-событийной-обработки). EVT-01–14 пока являются планом, успешный runtime-прогон не заявлен.

| Новый вход / риск | Требуемая защита | Проверка |
|---|---|---|
| Webhook из helpdesk: подделка, лишние поля, большой пакет | Проверка подписи, типа, размера и прав до записи; текст читается из разрешённого снимка тикета | EVT-12 |
| Повторы и поток событий расходуют бюджет | Дедупликация event_id и тикет/версия, конечная очередь и общие лимиты; известный дубль подтверждается без новой задачи | EVT-02,03,08,09 |
| Старая версия и гонка с подтверждением | Сравнение current_input_version под блокировкой при записи результата и review | EVT-04–06 |
| Падение после API-вызова и неизвестное списание | Сохранить попытку и резерв до сети; не обнулять при рестарте; вложенные повторы входят в общий максимум два | EVT-10,11,13 |
| Просмотр или feedback запускает новую генерацию | Только два разрешённых типа события запускают анализ; review хранится отдельно | EVT-07 |

Подпись подтверждает источник события, но не делает текст клиента доверенной инструкцией модели. Event ingress и исходящий Helpdesk adapter — разные границы. Модель не получает права на отправку; учебный прототип не выполняет внешнюю отправку.
