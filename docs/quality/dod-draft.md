# Черновик Definition of Done команды

Версия: v0.3. Это единый черновик команды к Lab 2.

Пункт считается выполненным, если рядом есть проверяемое доказательство: ссылка, число или результат автоматической проверки. Автор PR добавляет доказательства, участник другой роли проверяет их.

## Product

PRD готов, если назван один конкретный сегмент, описаны 3–5 болей с обстоятельствами, указан MVP и есть измеримый North Star.

Доказательство: ссылка на docs/prd.md и review Product.

Гипотезы готовы, если у каждой есть способ проверки и условие, при котором она считается неверной.

Доказательство: ссылка на docs/hypotheses.md.

Глоссарий готов, если содержит 15–30 терминов своими словами и команда использует эти определения в документах и коде.

Доказательство: ссылка на docs/glossary.md и отметка командного согласования.

Бриф готов, если помещается на одной странице и читается вслух меньше чем за две минуты.

Доказательство: ссылка на docs/brief.md и время чтения. Текущий ориентир — около одной минуты.

Презентация готова, если каждый участник может объяснить сегмент, боли, решение, ограничения и результат своей роли.

Доказательство: ссылка на презентацию или сценарий выступления.

## AI Engineer

Research готов, если каждый внешний вывод имеет проверенную ссылку на первичный источник.

Доказательство: ссылка на docs/research.md.

Кандидаты моделей готовы, если описаны 2–3 варианта, токены одного сценария, стоимость и поведение при исчерпании бюджета.

Доказательство: ссылка на docs/model-candidates.md.

Первый эксперимент готов, если его можно повторить, а команда честно записала, что получилось и что не получилось.

Доказательство: ссылка на notebook, параметры запуска и фактический отчёт.

ADR-001 готов, если выбран подход, перечислены альтернативы и названа цена решения.

Доказательство: раздел ADR-001 в docs/research.md.

## Delivery

Репозиторий готов, если его структура совпадает с README.

Dev-среда готова, если после создания .env одна команда docker compose поднимает сервис без ошибки и не дольше 10 минут.

CI готов, если на открытом PR успешно проходят обязательные проверки.

Публичный deploy готов, если URL из README открывается вне локального компьютера и endpoint /health возвращает HTTP 200.

Доказательства Delivery: ссылка на открытый PR, зелёный CI run, публичный URL и результат проверки /health.

## Quality & Safety

Критерии успеха готовы, если у каждой метрики есть число и способ подсчёта, а каждая боль PRD связана с измеримым результатом.

Доказательство: docs/quality/success-criteria.md.

План golden dataset готов, если названы источники, формат, объём 30–50 примеров, владелец и правила работы с данными.

Доказательство: docs/quality/golden-dataset-plan.md.

Первые примеры готовы, если data/sample/golden.jsonl содержит 10 валидных уникальных записей и их происхождение указано честно.

Threat model готов, если для каждой основной угрозы описаны вред, контроль и проверка.

Доказательство: docs/quality/threat-model.md.

## Общее правило PR

Перед merge CI должен быть зелёным. В PR не должно быть секретов и реальных персональных данных. Изменения должен проверить минимум один участник, который не является автором.
