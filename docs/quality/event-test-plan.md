# LAB02: проверка событийной обработки

Содержательные evals модели и транспортные проверки разделены. Набор из 40 примеров Q-002 сохраняет исходные входы и эталоны. Инфраструктурные сценарии не увеличивают число модельных примеров.

| ID | Воздействие | Ожидаемый результат |
|---|---|---|
| EVT-01 | ticket.created | Одна задача, карточка без кнопки запуска |
| EVT-02 | Повтор того же event_id | Одна запись события и одна задача |
| EVT-03 | Разные event_id одной версии | Дедупликация по тикету и версии |
| EVT-04 | Новая версия при queued | Одна ожидающая задача последней версии |
| EVT-05 | Новая версия при running | Один активный разбор, одна ожидающая версия, старый результат не становится актуальным |
| EVT-06 | Подтверждение одновременно с сообщением клиента | Атомарная проверка версии, устаревший ответ не отправляется |
| EVT-07 | Просмотр, заметка, статус, review | Ноль новых задач и вызовов модели |
| EVT-08 | Достигнут MAX_RUNNING | Параллельность ограничена, остальные задачи ожидают |

| EVT-10 | Исчерпаны частота или токены | Запуск отложен, резерв сохранён |

| EVT-13 | Исчерпан deadline или повторы | manual_review с причиной, без клиентского черновика |
| EVT-14 | UC-01–04 на готовой карточке | Источники, режим и отдельное решение оператора сохранены |

## Измерения и DoD
Для каждого сценария фиксируются вход, конфигурация, ожидаемый и фактический результат, число задач и модельных вызовов. Аварийные сценарии включают состояние после рестарта. Время до карточки считается от приёма события, отдельно измеряются ожидание и latency модели. Сохраняются event_id, версия тикета, число попыток и состояние. Лимиты очереди, частоты, параллельности и токенов задаются конфигурацией. Общий deadline 55 секунд и максимум два вызова действуют на всю задачу, включая рестарты.

## Угрозы
Повтор webhook и шквал событий расходуют бюджет. Контроли: проверка подписи, дедупликация, общий rate limit, конечная очередь и резерв до вызова. Подмена ticket_ref не должна раскрывать чужую историю. Событие старой версии не откатывает текущую карточку. Review не запускает inference. Тексты клиента и БЗ остаются недоверенными данными.

## Ответственность
Delivery отвечает за очередь, lease, транзакции и актуальность. AI Engineer отвечает за общий лимит попыток, расход и безопасный отказ. Quality ведёт сценарии и доказательства результата. Product определяет смысл UC и действие оператора. Повторное прохождение пользовательских UC подтверждено участником 23.10.2026. Эти сценарии задают техническую приёмку новой архитектуры.
