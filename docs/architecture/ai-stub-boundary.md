# Временная граница интеграции Delivery / AI

08.10.2026. Использован незавершённый черновик AI Engineer, но окончательный AI API ещё не завершён. Delivery самостоятельно реализовал только минимальную заглушку для проверки каркаса. Это техническое предложение; согласие AI Engineer и изменение его OpenAPI не заявляются.

`POST /v1/analyze` принимает `request_id`, `ticket_ref`, `ticket_text`, `history`, `kb_version`. `history` — список объектов `{speaker: customer|operator, text: string}`. Поля идентификаторов и текста непустые; request/ticket refs до 100 символов, ticket text до 10000, history до 50 элементов, каждый текст до 10000. Временный каркас дополнительно ограничивает `kb_version` 100 символами и весь HTTP body 64 KiB. Эти два ограничения необходимо внести в будущий согласованный контракт или изменить адаптер. Неизвестные поля отклоняются.

| Термин Product/VO | Поле черновика / каркаса | Значение |
|---|---|---|
| Собранные данные | `known_facts` | Подтверждённые текстом/историей сведения; не предположения |
| Источники ответа | `evidence` | Версионированные утверждённые источники; в заглушке всегда пустой список |
| Предлагаемый маршрут | `mode` | `answer`, `clarify`, `escalate`; не выполняет назначение или отправку |
| Request ID | `request_id` | Непустой идентификатор операции, выбранный вызывающей стороной |
| Ссылка на тикет | `ticket_ref` | Непустая непрозрачная внешняя ссылка; схема/доступ определяются адаптером |
| Версия БЗ | `kb_version` | Выбранная вызывающей стороной версия разрешённого корпуса; не утверждается заглушкой |

Успех заглушки всегда возвращает `status=not_analyzed`, `mode=escalate`, `urgency=unassessed`, `evidence=[]`, `draft_reply=null`, `needs_human_review=true`. Все поля ответа из черновика присутствуют. Каркас не делает retrieval, модельный анализ и не возвращает уверенный ответ без источника.

400 — отсутствующие/неверные поля или JSON; 413 — body свыше 64 KiB; 503 на backend — AI недоступен, клиент переходит к ручному разбору. Методов `send`, `assign`, `approve` нет; вызовы дают 404. Реальные действия должны появиться только в backend после проверки прав и отдельного решения человека. Прототип моделирует это подтверждение локально и не вызывает API.

До интеграции LAB03: AI Engineer проверяет имена, ограничения, формат ошибок и использование версии БЗ; Product/VO подтверждает отображение терминов; Quality & Safety проверяет реальные права, контекст и угрозы. Для Delivery LAB02 требуется запускаемый каркас, поэтому отсутствие окончательного модельного API не блокирует создание этих заглушек.
