# Архитектура LAB02

## Исходники и рендер

- [Context PlantUML](context.puml) / [SVG](context.svg): оператор, специалист, система поддержки, LLM-провайдер и граница Support Triage.
- [Container PlantUML](container.puml) / [SVG](container.svg): ответственности и зависимости целевого MVP.
- [ERD PlantUML](erd.puml) / [SVG](erd.svg): две независимо принадлежащие сервисам БД и снимок provenance между ними.

PlantUML 1.2026.8 рендерит их локально с `--network none`. C4-библиотека встроена в фиксированный образ; удалённые изменяемые include исключены. Исходники описывают целевые ответственности. LAB02 запускает эти границы как заглушки; существование контейнера не означает реализацию всей подписанной бизнес-функции.

## Соответствие C4 и Compose

| C4 alias | Compose | Действительно реализовано в LAB02 |
|---|---|---|
| ui | ui | Статический интерактивный прототип UC-01–04, локальная симуляция и журнал в памяти страницы |
| api | backend | `/health`, прокси `/v1/analyze`, ошибки 400/413, ручной fallback 503 |
| ai | ai | Проверка временного запроса, безопасный `not_analyzed`, `escalate`, `needs_human_review=true`; без модели |
| kb | knowledge | `/health`; чтение утверждённых статей — следующая интеграция |
| kbdb | knowledge-db | PostgreSQL, начальная схема статей и версий |
| audit | triage-store | `/health`; запись карточки/review — следующая интеграция |
| db | triage-db | PostgreSQL, предложения, снимки источников, решения оператора |
| hd | helpdesk-adapter | `/health`; внешняя система не вызывается |
| provider | llm-adapter | `/health`; провайдер не вызывается |

C4-рёбра обозначают планируемые вызовы. Единственный работающий бизнес-вызов каркаса: backend → AI-заглушка. UI проигрывает синтетические сценарии независимо от AI. HTTP используется в локальном Compose, HTTPS на схеме — требование будущего внешнего развёртывания. Backend имеет доступ к `frontend` и `application`, но не к сетям БД. AI использует только `application`. Сети `application`, `triage-data`, `knowledge-data` — internal. Публикуются только локальные UI/backend порты. У каждой БД один будущий сервис-владелец и отдельный volume.

## Область проверки aact

Фиксированная версия: 3.0.0-beta.29. Четыре правила в [конфиге](../../aact.config.ts):

- `acyclic`: нет циклов зависимостей;
- `crud`: к БД обращается только repo, а repo обращается только к своей БД;
- `acl`: внешние системы вызываются только через адаптеры с ACL-тегом;
- `dbPerService`: у каждой БД один владелец.

`apiGateway` отключён осознанно: каркас — локальное рабочее место; публичного API-шлюза и отдельной сети провайдеров в нём нет. `cohesion`, `stableDependencies`, `commonReuse` не являются принятой политикой команды для этих черновых границ и не используются как критерий LAB02. Ноль нарушений относится к четырём включённым правилам, а не к всем возможным правилам или готовности к эксплуатации.

[Проверка](../../tests/architecture.cjs) дополнительно подтверждает, что модель содержит 9 контейнеров и 11 отношений. Четыре отрицательных контроля добавляют запрещённый внешний вызов, цикл, прямой доступ к БД и второго владельца БД; каждый соответствующий check должен обнаружить нарушение. Результаты и команды повторной проверки: [README](../../README.md).

## Контракт хранения

`database/schema.sql` — миграция 001 Triage DB. `database/knowledge-schema.sql` — миграция 001 Knowledge DB. ERD отражает SQL-ключи и поля. `proposal_evidence` сохраняет source key, version, title и excerpt как снимок: удаление или обновление знания не должно задним числом менять основание уже рассмотренной карточки. Пунктир ERD — логическое происхождение, межбазового FK нет.

SQL требует явного actor и подтверждения для действия, адресата для передачи и причину для отклонения. Отдельное предложение остаётся отделено от review. Проверка допустимости источника и прав оператора — обязанности будущих сервисов, а не доказанные свойства одного CHECK в SQL. Подробности временных полей: [граница интеграции](ai-stub-boundary.md).
