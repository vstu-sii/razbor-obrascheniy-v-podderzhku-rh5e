# UC-01 — Подготовить обоснованный ответ

**Актёр:** оператор первой линии. **Цель:** ответить на типовой текстовый вопрос с проверяемым основанием. **Контекст:** открыто обращение русскоязычного B2B SaaS; у оператора есть право видеть историю и утверждённую базу знаний. Отправка ответа остаётся действием оператора.

**Предусловия:** текст обращения и история доступны; в утверждённом источнике есть ответ на вопрос; внешние действия от имени клиента не требуются.

## Основной сценарий

1. Оператор открывает тикет и запускает разбор.
2. Система показывает карточку: суть, известные факты, категорию, объяснение срочности, подходящие источники, недостающие данные и следующий шаг.
3. При достаточных основаниях система предлагает режим `answer` и черновик, привязанный к конкретным источникам. Она не отправляет сообщение.
4. Оператор открывает источники, сверяет факты с историей, при необходимости правит черновик.
5. Оператор подтверждает отправку в интерфейсе поддержки.
6. Интерфейс показывает факт отправки и сохраняет использованный оператором текст и контекст решения.

**Результат:** клиент получает только подтверждённый оператором ответ; оператор может показать, на каких источниках он основан.

**Альтернативы:** если источник подтверждает только часть обращения, неподтверждённая часть явно отмечается; полный ответ в режиме `answer` не предлагается. Оператор не отправляет такой черновик и переходит к [UC-02](uc-02-clarification.md) или [UC-03](uc-03-escalation.md). Если черновик неверен, применяется [UC-04](uc-04-review-rejection.md). Если поиск недоступен, система явно сообщает об отсутствии основания и не предлагает уверенный ответ.

**Правило приёмки:** нельзя получить отправленное AI сообщение без явного действия оператора; каждый существенный факт черновика можно проверить по показанному источнику или истории. Конкретные пороги точности и задержки находятся в PRD как рабочие предложения, не как результат теста.
