# UC-01: проверить автоматически подготовленный ответ

Актёр: оператор первой линии. Цель: получить обоснованный ответ на типовой вопрос. Контекст: синтетический тикет и утверждённая статья доступны системе.

1. Система принимает событие нового обращения и сохраняет задачу.
2. Исполнитель готовит карточку. UI показывает очередь, обработку и результат.
3. Оператор читает карточку, исходный текст и источник.
4. Сверяет каждый факт. При ошибке переходит к UC-04.
5. Подтверждает решение с причиной. Система проверяет актуальность версии.
6. Повторное открытие показывает исходное предложение и сохранённое решение.

Результат: решение оператора сохранено, сообщение клиенту не отправляется. При недостатке данных используется UC-02, при риске или отсутствии основания UC-03. Повтор события не создаёт лишнюю задачу. Старая карточка остаётся в истории и не подтверждается.

Приёмка: карточка появляется после сохранения обращения без отдельной команды разбора, источник доступен, решение читается после открытия. Доказательства технического пути и решение Product перечислены в [приёмке](../acceptance.md).
