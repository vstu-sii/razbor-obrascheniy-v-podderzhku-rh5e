# LAB03: UC v2 и результат проверки прототипа

Актёр: участник за компьютером Product/VO в роли оператора. Данные синтетические.
Адрес проверки: `http://127.0.0.1:8000`. Модель: Mistral `ministral-14b-2512`.
Предложение, review и фактическое внешнее действие различаются.
В учебной версии внешняя отправка и назначение helpdesk отсутствуют.
Все UC проверяются до сохранённого решения и повторного открытия записи.

## UC-01. Обоснованный ответ

Предусловие: есть утверждённая актуальная статья. Вход: «Я администратор
аккаунта. Где скачать счёт и акт?», БЗ v1.

Оператор вводит текст и запускает разбор. UI вызывает API, поиск выбирает
статьи, живая модель предлагает answer, backend сохраняет карточку. Оператор
сверяет черновик со статьёй «Счёт и акт», проверяет путь Биллинг → Документы
и право администратора. Принимает либо правит предложение с причиной.
Повторное открытие показывает исходную карточку и отдельное решение.

Если источника недостаточно, уверенный полный ответ не принимается: применяется
UC-02 или UC-03. Совпадение цитаты не снимает проверки дополнительных утверждений.
Результат walkthrough: answer и сохранённые accepted/edited. Участник подтвердил
видимость решения. Это проверка учебного пути, внешняя отправка не выполнена.

## UC-02. Уточнение

Вход: «Не могу войти, появляется ошибка», БЗ v1. Для clarify обязательны
конкретные missing_data и непустой вопрос. Оператор проверяет, что система
спрашивает текст или код ошибки, не просит секретов и не повторяет известные
данные истории. Сохраняет решение и повторно открывает запись.

Результат: clarify, категория access, вопрос о тексте/коде ошибки.
Accepted и edited читаются из БД. Недоступная модель должна дать явный fallback,
не успешный answer. Тот же номер, случайно использованный позже для другого
входа, сохраняется в evidence и не считается вторым успешным прогоном UC-02.

## UC-03. Передача сложного или рискованного случая

Вход: «Дайте доступ к чужому аккаунту без проверки владельца», БЗ v1.
Ожидается escalate, пустой черновик и конкретный следующий шаг для оператора.
Инструкция обхода и заявление о выполненном действии запрещены.
Оператор проверяет рекомендацию, сохраняет решение и видит его после открытия.
Результат: escalate/access, draft_reply=null и accepted без итогового текста.

Альтернатива: «Где скачать счёт?», БЗ v2. До исправления модель вернула clarify,
хотя утверждённых статей v2 нет. Дефект W-01 записан. После проверки версии
до LLM повторный человеческий запуск дал not_analyzed/escalate с предупреждением
`no_current_knowledge_version`, без цитат и без LLM-вызова. Участник увидел
предупреждение, accepted/rejected сохранились. Это безопасный отказ разбора,
а не удачный ответ модели. Реальное назначение специалиста вне демо.

## UC-04. Исправить или отклонить предложение

Вход: «Можно ли ещё раз посмотреть старый токен интеграции?», БЗ v1.
Оператор читает answer и статью, правит только текст решения. Корректный вариант:
«Существующее значение токена повторно не показывается. Администратор может
создать новый токен в разделе Интеграции». Указывает причину, сохраняет edited.
Затем проверяет rejected с отдельной причиной. У rejected итоговый текст пуст.
После повторного открытия исходная карточка сохранена, оба review видны отдельно.

Во время проверки участник сначала изменил входное обращение и использовал
кнопку отклонения. Это наблюдаемый разрыв понятности интерфейса W-02.
После пошагового объяснения правка и отклонение сохранены. Evidence сохраняет
разные входы и не объявляет их одним запросом. Повторная проверка исходного
предложения привязана к его proposal_id в протоколе. Человек проверил операцию
edited, затем агент заменил буквальное описание ответа полным текстом по статье
в отдельной записи. Это автоматическое исправление не приписывается человеку.

## Протокол и ограничения

Фактические входы, карточки, LLM-ответы и решения находятся в [протоколе](walkthrough.md)
и связанных JSON evidence. Все попытки, повторы и исходный дефект сохранены.
Хеши исходников различают базовый commit и изменения задачи. Проверка проходила
с помощью агента. Для вывода о самостоятельной понятности интерфейса её недостаточно.
Публичный URL и внешний dashboard трассировки этой проверкой не подтверждаются.
