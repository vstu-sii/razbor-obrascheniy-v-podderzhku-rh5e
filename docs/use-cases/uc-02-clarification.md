# UC-02: проверить уточняющий вопрос

Актёр: оператор первой линии. Цель: получить сведения, без которых нельзя обоснованно ответить. Контекст: автоматически подготовленная карточка неполного обращения.

1. Оператор открывает готовую карточку и исходную историю.
2. Проверяет конкретный пробел и предлагаемый вопрос.
3. Убирает повторный запрос известного факта и любые запросы секретов.
4. Сохраняет принятое или исправленное решение с причиной.
5. Повторно открывает карточку и видит отдельное решение.

Результат: утверждённый вопрос сохранён в учебной системе. Реальная отправка остаётся за границей MVP. Новое сообщение клиента создаёт новую версию и автоматический разбор. При ручном исходе оператор видит причину и продолжает работу сам.

Приёмка: вопрос соответствует пробелу, не просит пароль, токен или код 2FA, сохранённый текст доступен. Основания указаны в [приёмке](../acceptance.md).
