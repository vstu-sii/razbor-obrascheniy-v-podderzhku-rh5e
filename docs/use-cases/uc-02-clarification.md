# UC-02 — Уточнить недостающие данные

**Актёр:** оператор первой линии. **Цель:** запросить ровно те сведения, без которых нельзя безопасно продолжить разбор. **Контекст:** обращение неполное или неоднозначное; история не содержит нужного факта.

**Предусловия:** по событию создания обращения система автоматически подготовила карточку `clarify`; оператор видит исходный текст, историю и конкретные недостающие сведения.

## Основной сценарий

1. Оператор открывает готовую карточку из очереди. Разбор уже запущен событием создания обращения.
2. Система отделяет известные факты от предположений и перечисляет недостающие данные с причиной, зачем они нужны.
3. Система предлагает один понятный уточняющий вопрос и отмечает, что обоснованного ответа пока нет.
4. Оператор сверяет список с историей, убирает уже известное и подтверждает текст вопроса.
5. Оператор отправляет вопрос клиенту через интерфейс поддержки.
6. Тикет остаётся ожидающим ответа; карточка сохраняет контекст для следующего разбора.

**Результат:** клиент получает конкретный вопрос без повторного запроса известных сведений; ответ по существу пока не обещан.

**Альтернативы:** если история уже содержит факт, оператор дополняет карточку и переходит к [UC-01](uc-01-grounded-answer.md). Если вопрос касается чувствительных данных или полномочий, оператор не запрашивает их в свободной форме и передаёт случай по [UC-03](uc-03-escalation.md). Если клиент отвечает, его новое сообщение создаёт событие для разбора актуальной версии тикета. Если клиент не отвечает, дальнейший маршрут определяется правилами службы поддержки, а не AI автоматически.

**Правило приёмки:** вопрос опирается на явно отмеченный пробел; отправка требует действия оператора; система не подставляет выдуманный факт.
