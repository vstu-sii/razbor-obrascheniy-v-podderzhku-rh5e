# LAB04: итерации каскада, поиск и расходы

AI Engineer, 12.11.2026. Требования: [СИИ](https://sii.sergeivolchkov.ru/labs/lab4).
Mistral → при непрошедшей проверку карточке Sol → важный/неразрешённый случай
человеку. Обычные answer/clarify завершаются автоматически. Модель не выдаёт
права, не меняет аккаунт и не отправляет сообщения во внешний helpdesk.

## Данные и гипотезы

Исторический A/B v1/v2 сравнивал промпты Mistral на восьми одинаковых входах,
порядок чередовался. Новый парный опыт сравнивает обычное и компактное
представление одного JSON-контекста каскада. Набор диагностический, после правок;
это не held-out accuracy и не доказательство промышленной надёжности.

Гипотезы: проверять поиск до правки промпта; передавать те же данные меньшим
JSON; повтор проверенного ответа брать из кэша без генерации. План, вход,
источники, hashes и лимиты записаны до вызовов:
[config.json](../../ml/experiments/lab4/live-context-verified-20261112/config.json).

## Сначала проверка поиска

[Построчные результаты](../../ml/experiments/lab4/offline-final-20261112/offline.json):
13 сценариев (10 v3 и 3 support-policy), девять с обязательными статьями.
Полное покрытие required IDs на 9/9 положительных входах. Остальные четыре
не входят в знаменатель положительного retrieval. Это не precision и не
оценка смысловой применимости всех найденных фрагментов.

BM25 ищет по approved-статьям закреплённой версии. Top-3 отсутствует;
для Sol остаётся бюджет payload, для Mistral — техническое окно. Компактный
JSON не удаляет статей/полей: равенство декодированных данных проверено
для обоих провайдеров на всех 13 входах.

## Текущий каскад и настоящий новый A/B

Replay прежних raw-card/assessment через текущие проверки: 13/13 ожидаемых
режимов. Это проверка системы на прежних ответах, не 13 новых генераций.

Новый вход: «Где администратору скачать счёт и как пошагово включить двухфакторную
аутентификацию через приложение?»; KB support-20261112.

| Контекст | Модель | Результат | Input | Output | Время модели |
|---|---|---|---:|---:|---:|
| Обычный JSON | Mistral | answer, проверки пройдены | 3915 | 1237 | 23021.918 мс |
| Компактный JSON | Mistral | answer, проверки пройдены | 3894 | 1168 | 21939.402 мс |

Input уменьшился на 21 токен, 0.54%. Разницу output/latency на одной паре нельзя
целиком приписывать форматированию. Sol не вызывалась: Mistral справилась.
Оба raw/final независимо проходят актуальную cascade-схему и provenance gate.
В живом опыте использована совместимая raw-card схема из прежнего adapter;
отдельный replay подтверждает соответствие актуальному публичному контракту.
Начальные CA-отказы до HTTP сохранены отдельно; они не считаются генерацией,
резерв снят по not_sent. Проверка TLS не отключалась.

оба cache_hit с attempts=0, без нового HTTP. В offline replay семь пар
уменьшили число нужных генераций с 14 до 7. Это контролируемая повторная
нагрузка, не оценка доли повторов реальных клиентов или семь новых списаний.

## Решение

Приняты компактный JSON и кэш проверенных обычных answer: 300 с / 128 записей
на процесс. Ключ: authenticated actor, обращение/история, KB snapshot,
модель/схема/промпт/код проверок. Изменения дают промах. Clarify/escalate,
важные ответы и ошибки не кэшируются. Auth и reservation не обходятся.

Цитата и assessment не доказывают смысловую истинность. Отсутствие статьи
не означает отсутствие функции сервиса. Нужен независимый набор Quality.
Новые карточки не объявлены заново одобренными человеком: старые оценки
относятся к старым версиям ответов.
