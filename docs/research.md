# Research и ADR-001

Дата проверки источников: 17.09.2026.

## Подход 1. Прямой prompt

Прямой запрос к LLM подходит как минимальный baseline: в инструкции можно явно задать ожидаемый результат и критерии успеха. Это соответствует рекомендациям официальной документации OpenAI по prompting: [Model guidance — Prompting](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.5#prompting).

Ограничение для нашего продукта: модель не получает актуальные статьи внутренней базы знаний, если мы отдельно не передали их в контекст. Поэтому direct prompt можно использовать для сравнения, но нельзя считать достаточным решением для ответа по изменяемой БЗ.

## Подход 2. RAG

Retrieval позволяет искать релевантные фрагменты по запросу, ограничивать поиск фильтрами и получать найденный текст вместе с оценкой релевантности. Это подтверждает официальный метод поиска по vector store: [OpenAI Vector Store Search](https://developers.openai.com/api/reference/cli/resources/vector_stores/methods/search).

Для нашего продукта это означает, что ответ можно связать с конкретными версиями статей, а отсутствие подходящего фрагмента использовать как основание для clarify или escalate.

Цена подхода: нужно создать и обновлять индекс, хранить версии статей, измерять Recall@3 и обрабатывать ситуации, когда retrieval вернул нерелевантный фрагмент.

## Подход 3. Fine-tuning

Supervised fine-tuning требует подготовленных примеров корректных входов и выходов и отдельного цикла оценки. Формат и процесс обучения описаны в официальной документации: [OpenAI Supervised fine-tuning](https://developers.openai.com/api/docs/guides/supervised-fine-tuning).

В начале проекта у команды есть только 10 синтетических seed-примеров, поэтому данных недостаточно для обоснованного fine-tuning. Кроме того, fine-tuning не заменяет обновление фактов в базе знаний.

## Подход 4. Агент

Агентная архитектура полезна для многошаговых процессов с инструментами, состоянием и действиями. Возможности агентов и подключаемых инструментов описаны в официальной документации: [OpenAI Agents](https://developers.openai.com/api/docs/guides/agents).

Наш MVP не выполняет внешние действия и не изменяет данные. Он делает один контролируемый разбор и передаёт результат человеку. Поэтому многошаговый агент добавит оркестрацию и новые точки отказа без необходимого продуктового результата.

## Структурированный результат

Карточка должна соответствовать JSON Schema, чтобы API и автоматические проверки могли надёжно читать поля. В API режим json_schema используется для Structured Outputs и обеспечивает соответствие переданной схеме: [OpenAI Responses — Structured Outputs](https://developers.openai.com/api/reference/cli/resources/beta/subresources/responses#responses-beta_response_format_text_config).

Соответствие схеме гарантирует форму, но не истинность содержания. Поэтому значения отдельно проверяются по golden dataset и базе знаний.

## ADR-001. RAG и структурированная карточка

Решение: использовать retrieval по утверждённой базе знаний и передавать найденные фрагменты LLM для заполнения фиксированной JSON Schema. Если подтверждённого фрагмента нет, система выбирает clarify или escalate.

Почему выбран RAG: продукт должен отвечать по изменяемой БЗ и показывать оператору источники. Vector Store Search возвращает релевантные фрагменты и поддерживает фильтры, что позволяет учитывать версию и область статьи: [источник](https://developers.openai.com/api/reference/cli/resources/vector_stores/methods/search).

Почему не direct prompt: он остаётся baseline, но без переданного контекста не даёт модели доступа к актуальной внутренней БЗ. Рекомендации по prompt помогают управлять результатом, но не добавляют отсутствующие данные: [источник](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.5#prompting).

Почему не fine-tuning: у команды пока нет устойчивого размеченного корпуса, а процесс требует подготовленных обучающих примеров и оценки: [источник](https://developers.openai.com/api/docs/guides/supervised-fine-tuning).

Почему не агент: MVP не вызывает внешние инструменты и не выполняет многошаговые действия, для которых предназначена агентная архитектура: [источник](https://developers.openai.com/api/docs/guides/agents).

Цена решения: команда должна поддерживать индекс и версии БЗ; ошибка retrieval может привести к неверному источнику; поиск увеличивает latency и стоимость; нужны golden dataset, Recall@3 и ручная проверка содержательных значений. Structured Outputs решает проблему формы ответа, но не гарантирует фактическую правильность: [источник](https://developers.openai.com/api/reference/cli/resources/beta/subresources/responses#responses-beta_response_format_text_config).
