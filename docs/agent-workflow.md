# LAB03 Delivery: агентная разработка и review

## Задача

Перевести работающий ручной прототип на событийные UC Product и архитектуру
LAB02 ADR-003. Сохранить карточки, историю и явное решение оператора.
Требования преподавателя: frontend/backend, БД и миграции, общий Compose,
публичный прототип и этот отчёт. Командная событийная архитектура добавляет
дедупликацию, версии, лимиты, lease и восстановление.

## Что сгенерировал агент

- Сохранённую очередь, миграцию 003 для SQLite/PostgreSQL и журнал попыток.
- Приём подписанного metadata webhook, отдельный ingress ACL и доверенные снимки.
- Исполнитель backend с общими квотами и отдельный AI API с service auth.
- UI создания события, ожидания, версий и просмотра трасс; прежний review сохранён.
- Compose всех работающих процессов, проверки и инструкции размещения.

## Что проверил и исправил агент при review

- Убрал ручной inference из обычного UI и закрыл прежний endpoint HTTP 410.
  ENABLE_LEGACY_ANALYZE используется только изолированными тестами старой совместимости.
- Разделил operator/service/webhook секреты, не менял их на публичные константы.
- Не держит транзакцию во время сети. Дедупликация и квоты работают до вызова.
- Ограничил вложенные повторы: одна попытка адаптера на запись model_attempt.
- Добавил fencing при истёкшем lease и запрет review старой версии, включая SQL.
- Сохранил исторические строки при миграции и не приписал им версию задним числом.
- Пересмотрел прежние тесты миграций: теперь ожидаются версии 1, 2 и 3.
- Разделил ожидание первой попытки, model latency и end-to-end latency в трассе.

## Проверка

22 локальных API/SQL теста, 15 тех же событийных сценариев на настоящем
PostgreSQL, 3 startup, 13 прежних Quality/API и 3 Product регрессии проверяются
отдельно. Полный Compose проверяется через реальные HTTP-запросы, подписанный
ingress, отдельный AI, повтор события, новую версию, stale review и рестарт.
Браузерный прогон проверяет авторизацию, источники, подтверждение/отмену,
исправление, историю, передачу в очередь специалиста и сетевые ошибки.
Это агентное техническое review, не независимая человеческая приёмка.

## Оставшаяся внешняя зависимость

Новый публичный сервис участника отвечает с architecture=event-queue-v1.
Подтверждены UI/health 200 и защита API 401. Нужен авторизованный публичный
прогон и проверка после рестарта; фактический SHA из панели не прочитан. Качество extractive и внешний LLM/
Langfuse не объявлены проверенными этой работой. Реальный helpdesk не подключён:
используется явно обозначенный симулятор и готовый контракт trusted adapter.
