# LAB04: Quality & Safety

Ветка содержит Quality workflow, два отчёта и тесты с доказательствами.
Для автономного CI в tests/runtime/ включён минимальный неизменённый снимок
приложения из SIISKI, ревизия 84d544ed8a1194e91b27fdae5cc60578975e785a.
Публикация этой зависимости отдельно разрешена участником 27.10.2026.
Это объект тестирования, а не вторая развиваемая реализация приложения.

В снимке 25 файлов: backend, контракт/схема, SQL-миграции, модельный адаптер,
инструкции, guard, frontend, синтетическая БЗ и requirements. Документов
других ролей, Codex, .env, ключей и машинного контекста нет. Исходники
сохраняют содержание исходной ревизии; их нормализованные SHA-256 проверяются
по runtime-manifest.json до импорта. Ruff проверяет тестовый код; отдельный
конфиг runtime сохраняет снимок без форматирования его исходников.

CI больше не скачивает закрытый SIISKI и не требует секретов. Каждый PR
запускает полный replay 49 записей / 38 групп через этот снимок с прежними
порогами, шесть контрактов, EVT-01–14 SQLite/PostgreSQL и AT-01–16.
Это повторная обработка настоящих сохранённых ответов Mistral, а не новый
API-прогон. Raw LLM и системные метрики разделены. Дубликаты не увеличивают n.

Из корня ветки:

```sh
python -m pip install -r tests/runtime/requirements.txt
python tests/evals/evaluate_model.py --require-targets
python -m unittest discover -s tests -p quality_contracts.py -v
python tests/evals/runtime_checks.py --output-dir /tmp/lab4-events
python tests/evals/security_checks.py --output /tmp/lab4-security.json
```

Для проверки другой копии той же ревизии можно задать LAB04_RUNTIME_ROOT.
Несовпадение исходников с manifest завершает проверку ошибкой.
Для PostgreSQL используется только выделенная синтетическая БД lab04_audit,
пользователь audit, пароль synthetic_lab04_only, loopback:18093. Флаг
--postgres очищает именно её тестовую схему. Рабочую БД использовать нельзя.
CI создаёт этот сервис отдельно.

`quality_contracts.py` запускается в Quality gates. Обычный CI отдельно
проверяет историческое приложение app/ из main. Оно не подменяет объект LAB04.
`evidence/history/` хранит исходные сбои; текущие security/live/events/model
результаты и их знаменатели лежат в остальных каталогах evidence.
Development-набор и технический прогон не заменяют человеческую приёмку.

Первый CI действительно падал на доступе к закрытому SIISKI. Настройки доступа
не менялись. Эта зависимость устранена включением проверяемого снимка;
фактические статусы новых прогонов находятся в Actions текущего PR.
