# Разбор обращений в поддержку, LAB04 Delivery

Прототип автоматически разбирает создание обращения и новое сообщение клиента.
Оператор видит очередь и готовую карточку, проверяет источники и отдельно сохраняет
решение. Отправка сообщений и изменение внешнего helpdesk не реализованы.

## Запуск

Из корня этой папки: `docker compose up -d --build --wait`.
Для повторного запуска достаточно `docker compose up -d`.
Создавать `.env` не требуется: PostgreSQL-пароль и три отдельных кода доступа
генерируются локально и сохраняются. Открыть http://127.0.0.1:8000/.
Код оператора получить локально командой:

```sh
docker compose exec -T app python -c "from backend.bootstrap import configure_database,operator_token; configure_database(); print(operator_token('/data'))"
```

Код вводится только в поле интерфейса. Не отправлять его в публичные PR/скриншоты.
Сервисы: `app`, `worker`, `ai`, `ingress`, `db`; `credentials` завершается успешно
после создания пароля. `docker compose ps` показывает состояние сервисов.
База и модельные сервисы не публикуют порты наружу. Ingress: localhost:8001/events.

В учебном источнике создать обращение, затем сохранить новое сообщение под тем же
номером. Оба действия создают события. Отдельной кнопки запуска AI нет.
«Показать сохранённые» выводит актуальные состояния, историю карточек и трассы.
Устаревшую карточку можно прочитать, но решение по ней блокируется с HTTP 409.
Если автоматический разбор не удался, виден статус ручной проверки.

## Архитектура и данные

[Реализация архитектуры LAB02](docs/architecture/lab03-runtime.md),
[миграции](migrations/003_event_queue.sql), [инструкция размещения](docs/deploy.md),
[отчёт разработки](docs/agent-workflow.md).
PostgreSQL содержит события, снимки, задания, попытки, карточки, review и трассы.
Повторная доставка не расходует новую попытку. Есть одна активная и одна ожидающая
версия тикета. Более новая ожидающая версия заменяет предыдущую.

Учебные настройки: MAX_RUNNING=2, MAX_PENDING=100, MODEL_REQUESTS_PER_MINUTE=20,
TOKEN_BUDGET=1000000. Это конечные ограничения, не измеренная пропускная способность.
Deadline 55 секунд от постановки, максимум два вызова суммарно на задачу, lease
30 секунд, один вызов не дольше 25 секунд. Неизвестный расход остаётся зарезервирован.
Бюджет не сбрасывается после рестарта и автоматически не пополняется.

## Проверки

`python -m pip install -r requirements.txt`

`python -m unittest discover -s tests -p "test_*.py" -v`

`npm ci && npm run test:ui` запускает браузерные проверки при заданных AUDIT_URL
и DEMO_OPERATOR_TOKEN для синтетической локальной среды. Для Linux установить
браузер Playwright и задать PLAYWRIGHT_CHANNEL=chromium.
SQLite используется изолированными тестами и как опциональный локальный режим.
Общий Compose и публичный Render используют PostgreSQL.
