## Запуск всей системы одной командой

Из корня этой ветки, с работающим Docker Engine:

```sh
docker compose up -d
```

Предварительное создание .env и DEMO_OPERATOR_TOKEN **не требуется**.
Compose соберёт app image при первом запуске. Статус: `docker compose ps`.
Локальный UI: http://localhost:8000, health: http://localhost:8000/health.
При занятых портах задайте PORT в окружении. Начальные миграции применяются
автоматически; повторный старт сохраняет существующие данные.

Без DATABASE_URL работает SQLite на persistent volume. Код оператора создаётся
случайно один раз. Получить его локально:

```sh
docker compose exec app cat /data/operator-token
```

Ввести код в UI, создать синтетическое обращение, проверить источники, указать
причину и подтвердить решение. Сохранённые обращения и review открываются после
перезапуска. Настоящих сообщений клиентам приложение не отправляет.

Для Neon задаётся DATABASE_URL; данные и код доступа хранятся в PostgreSQL,
поэтому не теряются на ephemeral Render. [Инструкция](docs/deploy.md).
Строку Neon и код оператора нельзя публиковать в Git или скриншотах.

## Ограничения

Режим extractive использует поиск и фрагмент статьи, **не генеративную LLM**.
Нерелевантные результаты оператор должен отклонять; качество модели не объявляется
принятым. Новый событийный worker из Product design ещё не реализован.
Langfuse dashboard не подтверждён. Бесплатный Render может засыпать и долго
отвечать при первом открытии. PostgreSQL хранит текущую LAB03 JSON-схему,
а не полный нормализованный дизайн LAB02. Чужие роли этим PR не принимаются.

Прежние файлы LAB01 сохранены как история. Корневой compose.yml и этот Render URL
относятся к текущей лабораторной 3. Старый chatgpt.site адрес не является продом LAB03.
